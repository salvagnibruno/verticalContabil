VISÃO GERAL
-----------
Este sistema é um painel de controle (dashboard) interno desenvolvido pela
Delta Gestão Pública para monitorar o status de entregas contábeis de seus
clientes municipais junto ao TCE-RS (Tribunal de Contas do Estado do
Rio Grande do Sul) e ao FNDE (Fundo Nacional de Desenvolvimento da Educação).

URL de produção: https://vertical-contabil.vercel.app
Repositório:     https://github.com/salvagnibruno/verticalContabil


================================================================================
MÓDULOS DISPONÍVEIS
================================================================================

1. PAD — Prestação de Contas Digital (TCE-RS)
   Monitora o envio mensal de demonstrativos contábeis ao portal do TCE-RS.
   Verifica, para cada cliente, se o envio do mês de referência foi realizado
   dentro do prazo (último dia do mês + 30 dias).
   Status possíveis: No Prazo | Atrasado | Não Enviado

2. SIOPE — Sistema de Informações sobre Orçamentos Públicos em Educação (FNDE)
   Monitora o envio bimestral ao portal do FNDE.

3. MSC, SIOPS, MGS, RREO
   Módulos adicionais para outros tipos de entregas contábeis.
   (Atualmente em desenvolvimento / dados simulados)

================================================================================
COMO O SISTEMA CONSULTA O PORTAL DO TCE-RS
================================================================================

MECANISMO DE CONSULTA
---------------------
A cada 10 minutos, o dashboard executa uma atualização automática via
JavaScript (setInterval com intervalo de 600.000 ms = 10 minutos), chamando
a função refreshModuleData() que dispara a consulta ao servidor.

O servidor (server.js) realiza uma requisição HTTP GET ao portal público do
TCE-RS, sem necessidade de autenticação (portal público):

  URL consultada:
  https://portal.tce.rs.gov.br/pcdi2/relatorios-recibos-envio.action
    ?cdOrgao={CODIGO_ORGAO}&ano={ANO}

O servidor faz o parse do HTML retornado, localiza a tabela de recibos de
envio e verifica se existe uma linha correspondente ao mês consultado.

LÓGICA DE CLASSIFICAÇÃO (parsePadStatus)
----------------------------------------
  - Linha do mês NÃO existe no HTML   → Status: "Não Enviado" (pending)
  - Linha existe + sem data conclusão → Status: "No Prazo" (on-time / processando)
  - Linha existe + data <= prazo      → Status: "No Prazo" (on-time)
  - Linha existe + data > prazo       → Status: "Atrasado" (late)

  Prazo = último dia do mês de referência + 30 dias corridos

PLATAFORMA QUE REALIZA AS CONSULTAS
------------------------------------
O sistema possui DOIS modos de operação para realizar as consultas ao TCE-RS:

  MODO 1 — SERVIDOR LOCAL (Preferencial)
  Plataforma: Computador Windows da equipe Delta
  Como ativar: executar "Iniciar Dashboard.bat" na raiz do projeto
  Porta: localhost:3131
  Vantagem: usa o IP real do escritório, que não é bloqueado pelo TCE-RS.
  O dashboard detecta automaticamente o servidor local ao carregar
  (tenta conectar em http://localhost:3131/api/health).

  MODO 2 — SERVIDOR VERCEL (Fallback automático)
  Plataforma: Vercel (cloud serverless, região São Paulo / gru1)
  URL: https://vertical-contabil.vercel.app/api/...
  Limitação: os IPs dos servidores Vercel podem ser bloqueados pelo
  TCE-RS (retorna HTTP 403). Neste caso, o modo simulado é ativado
  automaticamente como contingência.

  MODO 3 — SIMULAÇÃO (Contingência)
  Quando nenhum servidor está disponível, o dashboard exibe dados
  simulados com base em dados reais conhecidos (Jan/Fev/Mar 2026)
  e hash determinístico para meses sem dados reais.

DETALHAMENTO DO SERVIDOR LOCAL
--------------------------------
  Arquivo: server/server.js
  Como iniciar: duplo-clique em "Iniciar Dashboard.bat"
    (ou: cd server && node server.js)

  Endpoints disponíveis:
    GET  /api/pad-status?orgao={cod}&ano={ano}&mes={mes}
         → Status de um único órgão

    POST /api/pad-status-batch
         Body: { orgaos: [...], ano: "2026", mes: 1 }
         → Status de múltiplos órgãos em paralelo (máx 40 simultâneos)

    GET  /api/siope-status-batch
         → Status SIOPE via FNDE

    GET  /api/health
         → Health check do servidor

    GET  /api/debug
         → Diagnóstico: IP externo + teste de conectividade com TCE-RS

  Cache: resultados ficam em memória por 30 minutos, evitando sobrecarga
  no portal do TCE-RS em consultas repetidas.

COMPARTILHAMENTO EXTERNO (Cloudflare Tunnel)
---------------------------------------------
  Arquivo: iniciar_compartilhamento_cloudflare.bat
  Permite expor o servidor local via túnel Cloudflare (cloudflared),
  possibilitando acesso ao dashboard a partir de dispositivos externos
  (celular, outro computador) sem precisar abrir portas no roteador.

CLIENTES MONITORADOS
================================================================================

O sistema monitora atualmente ~110 entidades municipais do Rio Grande do Sul,
divididas entre Prefeituras Municipais (PM) e Câmaras Municipais (CM).

Os dados dos clientes (nome, código TCE-RS, código IBGE, tipo) são armazenados
no próprio arquivo dashboard_app.js (array CLIENTS_DATA) e persistidos no
localStorage do navegador para edições locais.

Exemplos de clientes:
  - PM Ametista do Sul    (cód. TCE: 88023)
  - PM Constantina        (cód. TCE: 45700)
  - PM Porto Mauá         (cód. TCE: 88050)
  (e outros ~107 municípios)

================================================================================
OBSERVAÇÕES TÉCNICAS IMPORTANTES
================================================================================

1. BLOQUEIO DE IP NO TCE-RS
   O portal do TCE-RS bloqueia IPs de provedores cloud (Vercel, AWS, etc.).
   Para consultas reais, é OBRIGATÓRIO usar o servidor local
   ("Iniciar Dashboard.bat") a partir do computador do escritório.

2. ATUALIZAÇÃO AUTOMÁTICA A CADA 10 MINUTOS
   O browser executa setInterval(() => refreshModuleData(true), 600000)
   que dispara nova consulta ao servidor a cada 10 minutos enquanto o
   dashboard estiver aberto. O servidor possui cache de 30 minutos para
   evitar sobrecarga no TCE-RS.

3. CONSULTA EM LOTE (BATCH)
   Ao carregar o módulo PAD, o sistema faz uma única requisição POST
   /api/pad-status-batch enviando todos os ~110 códigos de órgãos de uma
   vez. O servidor processa em paralelo (até 40 simultâneos por chunk)
   e retorna todos os status em uma resposta só.

4. BUG CORRIGIDO (18/05/2026)
   Corrigido falso positivo na identificação do mês: a busca por "1º mês"
   poderia incorretamente encontrar "11º mês" (Novembro) por substring
   match. Corrigido com ancoragem no delimitador HTML ">" da tag.
